# Runtime dependencies, pinned exactly.
#
# Every entry is `==`. A range like `fastapi>=0.115.0` resolves to whatever is
# current on the day the image is built, which means a version number stops
# identifying an artefact: two builds of "v1.0.0" get different code. That is
# the opposite of what a version number is for.
#
# These pins were read from the image that passed the round-42 regression suite
# (backend 17/17, HTTP 83/83, tag replay, upload, chunked upload, probes), so
# the set is known-good together, not merely recent.
#
# Bumping a pin is a normal change -- do it deliberately, and re-run the
# container regression before tagging, because these are the versions the
# migrations and the vector code were tested against.
#
# Removed 2026-09-20 after verifying zero imports anywhere under Docker/main:
#   httpx, requests-unixsocket, pandas, beautifulsoup4, lxml, plotly, rapidfuzz
# NOTE: dropping httpx also broke fastapi.testclient (an indirect consumer).
# Test-only extras now live in requirements-dev.txt; keep them out of here.
# (bs4/lxml/requests-unixsocket were crawling-era leftovers; the rewritten XP
# service no longer needs plotly on the server side -- the UI renders with
# plotly.js from npm.)
#
# `requests` is kept: services/ai_provider.py uses it to reach the operator's
# own local OpenAI-compatible /v1 endpoint.
